# Binding frontend reference

The updated TypeScript application on `experiment/liquid-glass@331326b` is the preferred visual guide, including its gradient background and frosted surfaces. The underlying `main@ee2a9ed` is the interaction guide for the Preact host. The rewrite changes the runtime and storage, not the product's visual identity. Do not replace it with an unrelated dashboard or a new palette.

The host reuses the original Orbit tokens from `src/lib/theme.css`, shared page/chat geometry from `style.css`, `polish.css` and `mobile.css`, and the actual SVG geometry from BrandMark/Icon. Component-scoped launcher, login/setup, primary navigation, connection notice and app-dock rules were ported into ordinary CSS. Unused legacy feature selectors were removed. Build CSS through esbuild so the shared token file is bundled into the executable's single stylesheet.

Retain minimum 44 px touch targets, 16 px phone inputs, safe-area spacing, keyboard/visual-viewport sizing, native dialog focus trapping, Escape closing only the top sheet, ordinary pinch zoom and reduced-motion support. Pending jobs survive closing chat or disconnecting the browser; conversation selection reconnects to them.

Voice dictation/read-aloud and owner-confirmed voice write suggestions are restored. Chat image attachments include upload, paste/drop, thumbnails, removal, persisted history and model vision input. Apps access their saved images through the scoped host bridge. The supported launcher’s quick actions are Let’s talk and Start a chat. App creation is conversation-led: the agent chooses the name and purpose, and the owner approves the build. Creating an app opens a conversation without requiring an upfront name. Approval opens the persisted build conversation with the original request preserved. Model choices load only when an active chat needs them, not from an invisible modal on every app launch.

The browser regression verifies computed reference colors and grid geometry, captures setup/login/launcher/settings/app/chat desktop/phone screenshots with synthetic data, checks nested modal Escape, a simulated software-keyboard viewport and the real shared iframe/action path. This is frontend evidence, separate from the pending real-account model test.

## Mobile review

The shared `web/core/mobile.css` layer keeps the Liquid Glass identity while normalizing phone inputs, 44–48 px controls, safe-area spacing, bottom sheets, readable helper text, long titles, search focus and unread badges. Conversation history leaves the phone keyboard closed until search is selected. Native dialogs retain focus trapping and lock background scrolling.

Settings forms keep failures inside the active sheet, preserve entered values and prevent duplicate saves. Schedules offer daily, weekday, Monday and hourly presets, an explicit UTC time and a custom cron option. Invalid action JSON receives a specific inline error. Saved presets use readable labels.

`web/test-mobile.mjs` reviews home/search, chat, voice, history, notification inbox, secret and schedule forms, app menus, versions and app chat at 320, 390, 768 and 1280 px. It exercises long titles, empty search recovery, keyboard-height form errors and saved schedule presets. The main browser driver also captures phone setup/sign-in, registration errors and app confirmation. Screenshots use synthetic data under `build-rust/screenshots/review-*.png`. These are Chromium checks; physical iOS/Android keyboard, microphone and native push presentation still require device testing.

Chat now uses a Markdown token parser rendered through trusted Preact elements. Raw HTML stays text and unsafe URL schemes are rejected. Notices and new-preview actions live above the composer; opening either preview button dismisses the bottom action for that revision. Home shows the notification inbox below apps. Visible replies are acknowledged before delayed push delivery. App archiving is reversible through Settings and pauses its schedules. Agent-selected emojis persist from build proposal to launcher.

Model work runs on the server independently of the browser connection. The chat shows queued, working, retrying and reconnecting states. Reload restores the latest job, including its friendly failure message. Continue saved work resumes eligible checkpoints; unknown action outcomes require review. Network reconnect never automatically resubmits a user write.
