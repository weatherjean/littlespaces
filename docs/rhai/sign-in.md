# ChatGPT connection

LittleSpaces signs in directly in Rust, without a Codex executable or private Codex cache. The Rust listener binds `127.0.0.1`. Local use defaults to a callback on its actual port at `/auth/callback`. OpenAI dynamic registration requires an HTTP loopback callback; substituting a VPS HTTPS domain as the redirect is not supported by this flow. The owner first signs into LittleSpaces, then chooses Continue with ChatGPT in Settings. Initial registration uses the persistent host identity and the app name LittleSpaces. Subsequent authorizations retain the verified subject/client mapping, including after disconnect. There is one connected ChatGPT registration in this workspace implementation.

The host generates one-time state, nonce and PKCE, verifies callback ownership/state, exchanges the authorization code, and validates the signed ID token against OpenAI's JWKS with issuer, audience, expiry, issue time and nonce checks. OAuth tokens are encrypted in the workspace database and excluded from app secrets/tools. App code has no access to these credentials. [Registration and sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in).

The model picker loads the account's catalog. Inference uses its selected slug, `store:false`, `stream:true`, and the public Responses endpoint. A partial stream is insufficient to dispatch tools; completion is required. Tokens refresh serially near expiry, without automatic inference retries. Disconnect attempts the discovery document's revocation endpoint and clears local tokens, reporting when remote revocation was not confirmed. [Models and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference), [accounts and sessions](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions).

The owner has completed fresh local sign-in, and a read-only diagnostic now returns seven available models. No model inference was issued by the agent during that diagnostic. Signed synthetic ID-token, state-binding, encryption and streamed-provider fixtures run routinely. Real VPS sign-in, token refresh and generation still need explicit testing with fresh user authorization; these requests can consume account usage. Do not copy private authentication files. Switching among multiple retained ChatGPT registrations remains deferred. The workspace has one owner and one active ChatGPT connection; the VPS callback path is described below.

## VPS public origin and a fresh callback tunnel

Configure `LITTLESPACES_PUBLIC_URL=https://your-domain.example` behind your TLS reverse proxy. This is an explicit trusted origin; forwarded headers do not select it. Owner cookies are Secure and CSRF checks use that origin. Configure `LITTLESPACES_OAUTH_CALLBACK=http://127.0.0.1:1455/auth/callback` and, on the computer running your browser, establish `ssh -N -L 1455:127.0.0.1:5175 user@your-vps` before connecting. Keep the tunnel open through authorization. The local callback is forwarded to the same Rust process on the VPS, which checks one-time state/PKCE/nonce, validates the originating owner session even when the domain cookie cannot reach loopback, exchanges credentials on the VPS and redirects back to the configured public origin. The VM keeps its own host ID and encryption key. No Codex cache or token file importer is involved.

This tunnel is an application adaptation of the documented loopback requirement, not a claim of a supported direct HTTPS redirect. OpenAI's documented VM procedure is local authorization and protected credential transfer. [VM guidance](https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms). The origin/tunnel authority separation is covered synthetically; a real VPS/reverse-proxy/OAuth exercise remains necessary. TLS proxy provisioning and Docker/Compose remain their later deployment stage.
