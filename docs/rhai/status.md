# Monolith rewrite status

This page is an implementation history, including limitations that later entries supersede. For the current single-user project, start with the [README](../../README.md), [contribution guide](../../CONTRIBUTING.md), and [release checklist](../releasing.md). The project remains experimental; historical checks are not a production qualification.

The application is implemented on `rework/rust-monolith-rhai`; the agreed sequence remains [monolith-rework.md](../monolith-rework.md).

The single Rust executable owns the fresh SQLite workspace, owner setup/login/session reset, encrypted secrets and ChatGPT state, direct OAuth/inference, streamed agent jobs, typed scoped authoring tools, Rhai actions, public-network HTTP, validation, publication, conflict-checked commits and schedules. It embeds the Preact shell and Preact/HTM runtime. Applets run in sandboxed iframes using an app/revision-bound bridge. No runtime Node, Codex, QuickJS or Bubblewrap is involved.

Backend tests, HTTP fixtures, dry runs, preview calls and live UI/chat/schedule actions use the same evaluator. Tests/previews use isolated records and synthetic secrets/HTTP. Publication binds backend test evidence and frontend verification to the exact immutable code/contracts/tests digest. Automated browser evidence and explicit owner preview approval are recorded as different kinds of verification. The optional Node/Playwright browser harness is development tooling, not a prerequisite for ordinary application startup or owner-reviewed publication.

Durable external-operation intent is written before dispatch. Incomplete responses preserve uncertainty and any status received; failures never erase evidence or imply rollback. Duplicate invocation IDs and unresolved effects block blind retries across revisions. Owner resolutions remain separate records and are unavailable to scripts/agent tools. Restart resumes checkpointed model jobs, reuses completed tool results and stops on unknown tool outcomes. Incomplete invocations remain interrupted. The server takes an OS workspace lock before recovery so a second process cannot interrupt an active host. Schedules disable themselves on stale publication or unresolved-effect errors.

Superseded Svelte/QuickJS/Codex/grant implementations, old source schemas, commands and root runtime manifests have been removed. Existing local databases/auth files and ignored build caches were preserved; Git history is the reference. Frontend dependencies live only in `web/`.

Verification: focused Rust regressions cover validation, atomicity, competing commits, cancellation/native-callback deadlines, read-only enforcement, admission, slow HTTP, interrupted effect evidence, owner authentication, signed OIDC checks and SSE completion. A development browser regression drives the real Rust streamed agent with a scripted local provider through failed generation, diagnostics, a fix, backend tests, actual iframe interactions, publication, live UI/chat calls and record-preserving updates. It also verifies the separate owner-review publication route and reconnects to a durable running job before closing the browser while that job continues. These fixtures are not evidence of real-model generation or real sign-in.

The owner completed fresh local ChatGPT sign-in; a read-only catalog diagnostic confirmed seven available models after the catalog-budget fix. That initial catalog repair issued no inference requests and used no private Codex cache. The subsequent owner-authorized live browser review established small-app generation and publication, as detailed below. The supported flow and sources are in [sign-in.md](sign-in.md). Linux AMD64/ARM64 CI is configured; those new jobs have not been observed locally. Builds and focused checks run locally on macOS with Rust 1.84.1.

The owner's first real greeting exposed a stream-assembly bug: the job retained reply deltas but saved an empty assistant message. Finalized `response.output_item.done` items are now retained when the successful completion envelope omits output, following the [streaming event contract](https://developers.openai.com/api/reference/resources/responses/streaming-events). They remain unavailable for tool dispatch without whole-response completion. Deltas alone cannot establish a final answer, and empty replies fail explicitly. The browser fixture now exercises separate finalized items with empty completion output; that stream fix is now also exercised by the live app-generation review below.

Release limitations remain explicit:

- Rhai cannot preempt blocking callbacks. Transport deadlines, bounded admission and cancellation/commit gates prevent late local commits, but native compilation/JSON/database work may return after the script deadline.
- Data/operation limits are not a hard per-action memory ceiling. Adversarial peak-memory/target-host measurements and the final containment decision remain release blockers; there is no QuickJS fallback.
- Browser harness verification and owner preview/runtime diagnostics have different coverage. Deployed agents use owner review when the development harness is absent.
- Real VPS/reverse-proxy/OAuth validation, production Docker/Compose, comprehensive system verification, backup/recovery exercises and release dependency packaging remain later stages.
- Image attachments, model vision input and app-scoped image access are implemented; image bytes currently live in the workspace database. Native web search is advertised, but real account search access and general upload browsing remain unverified. The earlier plan to store upload bytes as separate files has not been implemented.

Conversation-led app creation now lets the agent choose the name/purpose, then opens an approved build with context preserved. Voice dictation/read-aloud and single-use owner-confirmed write suggestions are restored. The preferred styling is the gradient/liquid-glass branch, with original interaction geometry retained. Public-origin configuration and a fresh SSH-forwarded loopback callback path are implemented without a token importer; a real VPS test remains necessary.

The app canvas refreshes after chat jobs so changes appear without reopening it. The original Liquid Glass branch was run separately with synthetic owner data for visual comparison; its styling is retained, including the restored home reload control.

The expanded Chromium suite covers the actual shell preview/publish buttons, preview isolation/reload, completed text and confirmation cards without page reload, back/forward and delayed-history races, running-job reconnect/cancel, failed typed/dictated sends, Voice route preservation, permission-error recovery, audio cancellation, late microphone callbacks, and phone keyboard layout. The live small-app pass establishes readiness for owner development testing; it does not establish arbitrary model output quality, real microphone recognition, deployed OAuth, or the release limitations above.

PWA manifest, home-screen icons, public-only offline cache, notification inbox and device-opt-in encrypted Web Push are restored. App notifications commit with records; the Rust worker queues due reminders and completed-chat notices for push delivery. Tests cover encryption/decryption, subscription validation, atomic notification changes, actual browser service-worker installation/offline behavior, inbox read state, and old-subscription recovery. Push transport and native notification display are simulated in browser fixtures; delivery through a real push provider still needs an opted-in device. Let’s talk has no text composer, offers a remembered speaking voice with preview, and filters novelty voices from automatic selection. Empty conversations stay out of history.

Home/build chats now load app planning, building, updating and managing skills, read the bundled SDK, fetch bounded official Rhai docs and advertise native Responses web search. Update/archive/restore use owner-confirmed proposals. AppCode can opt into app-isolated SQLite for relations/FTS5; database images commit atomically with records and notifications, with isolated tests/previews and bounded SQL execution. Native search account access has not been live-verified by this change.

Model streaming finishes at the provider completion event rather than waiting for HTTP EOF. Long-running model jobs now use a durable queue and checkpoints, with no total wall-clock deadline. Requests allow 600 seconds for headers or stream inactivity and 15 seconds to connect. Transient failures receive three retries with 10/20/30-second waits, respecting longer Retry-After guidance and preserving attempts across restart. Completed tools are not repeated; unknown dispatch outcomes require review. Failed/cancelled jobs can continue from safe checkpoints, and the 256-round budget can be extended explicitly. Browser reconnects restore job state without resubmitting writes. Every public error code has a friendly frontend message plus a safe fallback for unknown failures. App actions default to 60 seconds, configurable up to 300 seconds.

Model streams no longer have a cumulative wire-byte cap: repeated SSE envelopes and heartbeats do not represent retained output. Individual events and accumulated finalized items are bounded at 4 MiB; visible reply deltas remain bounded at 128 KiB. Stream bounds have distinct public errors rather than the generic workspace limit. Partial replies remain visible after failure/reload and are archived before retry/continuation. Expert mode shows function calls while the provider is generating them; unfinished calls are never dispatched. History polling acknowledges a new history version only after successfully fetching it.

Reliability verification includes synthetic-provider browser tests for disconnect/reconnect, exhausted retries and manual continuation, Rust checkpoint recovery/deduplication, error mapping coverage, and a virtual-time stream exceeding the former ten-minute job cap. These tests do not exercise real-account inference.

Approved builds now use automatic validated releases. Each release stores before/after records and SQLite snapshots, code references and retained image IDs. Version-bound migration plans run only against copies, check SQLite integrity/foreign keys, exercise current-data read contracts and optional explicit preservation probes, and commit exactly the tested data with code in one transaction. Existing-value changes and snapshot restores require owner review. The owner can revert code while retaining current data, restore a snapshot, or ask the model to prepare a selective merge. Unknown external effects remain fenced; recovery does not rewind external actions, delivered notifications, image uploads or schedules. These local snapshots are not independent disaster-recovery backups.

The dev launcher supplies automated browser verification. The opt-in real-model API creates separate workspaces, reuses only the in-process ChatGPT connection, mocks app HTTP and retains scenario evidence. Synthetic CI covers automatic release, approval UI, restore UI, test-workspace isolation, stale plans, cancellation and selective data preservation. The ordinary Rust host still starts without Node; automatic publication of new frontend code requires browser verification.

Real-model verification (2026-10-09): GPT-6.1-Sol passed all four isolated API scenarios: automatic SQLite app release with browser checks, additive migration preserving existing data, owner-confirmed restore of the older schema while retaining a newer note, and a destructive dry run that left live data unchanged. API assertions checked persisted SQL and records rather than trusting model prose. The first run exposed outdated model tool declarations; those were fixed and covered by a schema/host compatibility regression before the successful rerun. Owner app data was not used.

Authoring repair verification (2026-10-09): tool-specific argument schemas reject missing revision IDs and unsupported expected_version fields; invalid calls return required/optional/missing fields without exposing argument values. Browser failures are stored in revision diagnostics and returned by failed release validation, with completed step/assertion counts and a one-based failing step. Value/enabled assertions support state-based waits. The fixture release suite verifies failure → diagnostics → targeted patch → successful release. An isolated GPT-6.1-Sol run also completed this path using exactly one frontend text replacement; evidence: `build-rust/model-e2e/SPr4Gu2HScChUKP7x3a1fDuCee3t92pvfkN3Xp_oKcU/report.json`. The original user job was not resumed.

Production review (2026-10-09): see [readiness assessment](../production-readiness.md). Workspace ownership now precedes schema setup in both CLI and server; additive installation is atomic. Cancellation intent survives restart, transient failure of a terminal job-status write is retried without replaying tools, and accepted owner decisions outlive a disconnected request. Standard release builds exclude live-test routes and reject the synthetic-provider feature. The October 15 follow-up adds disposable workers and a versioned workspace upgrade; see the current readiness assessment for remaining deployment qualification.

Review follow-up (2026-10-15): successful invocation outcomes commit atomically with app data; scheduler batches retain undispatched work across status-write failure; push attempts use durable backoff. Version-4 workspaces migrate to version 5 with a pre-upgrade database snapshot. Owner history is paginated separately from model context. Storage cleanup is explicit and protects live data and recovery evidence. Execution moved into disposable worker processes with enforced heap budgets, deadline termination and Linux address-space limits. Historical in-process limitation notes above describe the earlier implementation; target-host production qualification is still required.
