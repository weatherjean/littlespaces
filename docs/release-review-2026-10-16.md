A later full browser run reproduced a storage failure during interrupted-stream recovery. Request diagnostics used a deferred transaction that read before writing; a concurrent writer could make the lock upgrade fail immediately. ## Second independent pass on `90a3221` (existing changes preserved)

This pass started from `90a3221f58c34c2b1e05e1debb966e4ffdaf5722` with **nine modified files**, read the release guidance and existing diff before editing, and retained those changes. It revisited setup/build entrypoints, the package allowlist and provenance, target-specific notice metadata and supplemental sources, privacy boundaries, deployment instructions, and CI ordering. The additional confirmed defects were in the separately shipped browser verifier:

- **HTTP redirect escape:** the origin allowlist used Playwright `route.continue()`. A synthetic allowed-origin endpoint redirected to a second loopback origin, which received a request. The routing callback does not re-check subsequent redirect hops. The verifier now fetches with `maxRedirects: 0` and rejects HTTP redirects before following them. Ordinary preview HTTP requests and backend action requests remain supported.
- **WebSocket escape:** HTTP routing did not cover WebSocket connections. A separate synthetic regression recorded an upgrade request at the second origin. The verifier now closes WebSocket routes without connecting to their servers; the existing preview protocol uses HTTP.
- **Completion/admission race:** a result could reach its caller while the previous browser context was still closing and `active` remained true. An immediate sequential verification then returned 503. Responses now follow context cleanup and admission reset. Genuinely concurrent requests still receive 503.

The standalone `node web/test-harness.mjs` regression runs only ephemeral loopback servers and temporary screenshots. It checks an ordinary allowed request, a direct outside-origin request, an allowed-origin redirect, a WebSocket attempt, and immediate sequential verification. Redirect and WebSocket cases were also run independently against the original verifier and failed as expected. Both architecture jobs now run this regression after installing Chromium and before the full browser suite and package upload. Deployment wording now states that all HTTP redirects and WebSockets are rejected. Playwright's [routing documentation](https://playwright.dev/docs/network) and the installed 1.63.0 implementation were consulted; these are application-level browser checks, not an OS network sandbox or proof against every browser transport. The probes use an authenticated verifier request and a synthetic preview host; they do not demonstrate unauthenticated access or a generated iframe bypassing the production CSP.

An optional service-worker blocking experiment was removed: Playwright's injected blocking code raised `SecurityError` inside the application's opaque sandboxed iframe, which the full browser suite correctly treated as a failure. The service-worker probe established registration, not an outside-origin request; no service-worker escape or fix is claimed. The retained changes address the independently reproduced redirect/WebSocket defects.

## Release qualification on 2026-10-20

The full clean-checkout browser suite on `5058b7a` exposed a verifier shutdown race: `APIResponse.dispose()` could reject after its browser context closed, escaping the route callback and terminating Node. Response disposal now tolerates an already-closed context, and context teardown first unregisters routes with Playwright's `ignoreErrors` behavior. The focused regression adds twelve verification cycles with concurrent background HTTP requests, followed by an ordinary verification to check continued availability. It passes alongside the existing privacy, origin, redirect and WebSocket checks. This is a verifier lifecycle fix; it does not change app data or the workspace format.

Fresh local checks on the preceding candidate passed 75 Rust unit tests, seven executable integration tests, Clippy, formatting, 15 packaging regressions, the isolated Traefik smoke, and an optimized package's production/recovery smoke. Current npm and Cargo audits found no known vulnerabilities; the two previously documented unmaintained-crate warnings remain. Redacted history and clean-source scans found only the documented synthetic OIDC fixture key. Local Markdown file links and branding archive path inventories passed their bounded checks.

Hosted ARM64 browser runs on `10929ad` then exposed job-poll storage errors during app updates. A focused regression reproduces the same failure by holding an exclusive database lock for 600 ms: the former 250 ms connection timeout returns `Storage`. Connections now wait up to five seconds for SQLite lock admission, without replaying transactions or application writes. The terminal-finalization regression still holds a writer beyond the configured deadline to exercise its durable retry path. The SDK's outdated in-process containment paragraph was also aligned with the already-implemented disposable worker limits.

Final browser and hosted architecture evidence must refer to the revision containing these fixes. A preceding candidate's package and CI results do not qualify its successor. Repository visibility and enabling GitHub private vulnerability reporting remain coordinated public-launch actions.
